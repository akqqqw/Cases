# Разложи по полкам

Казуальная браузерная головоломка (Sorting / Match-3): на полках лежат товары, игрок
перетаскивает их по свободным ячейкам и собирает **три одинаковых предмета рядом** —
тройка исчезает, полка освобождается. Уровень пройден, когда цель выполнена.
У каждого уровня ограниченный запас ходов.

Работает и на ПК (мышь), и на телефонах/планшетах (touch + drag), портрет и ландшафт.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm start          # то же самое, но сам ставит зависимости (для свежей песочницы)
npm run build      # tsc -b + vite build → dist/
npm run preview    # предпросмотр собранной версии
npm test           # 519 тестов: движок, уровни, магазин, задания дня, подарок дня, МАСТЕР,
                   # события, площадка Яндекс Игр, сохранения, реклама, рейтинг, покупки,
                   # флаги, сборка архива, фоны экранов, UI
npm run typecheck  # только проверка типов (ничего не пишет на диск)
npm run package    # боевая сборка + ZIP для Консоли → artifacts/shelf-sort-yandex.zip
```

Локальная проверка площадки без Консоли разработчика: `http://localhost:5173/?sdk=mock` —
поднимается заглушка SDK (`src/platform/mock.ts`), а `?lang=en` переключает язык интерфейса.

Заглушка отвечает не только за язык и разметку: у неё есть игрок, облако (`getPlayer`,
`setData`, `getData`, `setStats`), реклама (`ysdk.adv`), лидерборды (`ysdk.leaderboards`),
покупки (`ysdk.payments` — пять товаров с ценами Консоли) и флаги (`ysdk.getFlags`),
поэтому и карточку «Облачное сохранение» в паузе, и полноэкранную рекламу, и ролик за
награду, и таблицу рейтинга, и блок «Премиум» в магазине можно проверить в превью по-настоящему: прогресс уезжает в память
заглушки и возвращается при следующем запуске вкладки, межстраничная реклама «закрывается»
кнопкой в правом нижнем углу, а в таблице рейтинга видны «другие игроки» и наш собственный
результат.

Флаги можно проверить и без Консоли: `http://localhost:5173/?flags=ad_rewards_per_day=5,coins_multiplier=2`
переопределяет значения до запроса к площадке (см. раздел «Флаги экспериментов»).

На боевом хостинге Яндекс Игр SDK подключается сам: игра запрашивает `/sdk.js` рядом
с `index.html` (именно этот путь ждёт площадка), в обычном браузере запрос тихо
игнорируется и игра работает как веб-версия.

## Стек

TypeScript · Vite · React 19 · Phaser 3.90 · Zustand · IndexedDB.

## Что готово

### Этап 1 — базовый геймплей
- Полки-ячейки, drag-and-drop (мышь и touch), сборка тройки, исчезновение с частицами.
- Ходы, победа/поражение, отмена хода, подсказка, пауза, перезапуск уровня.
- 24 вида товаров с уникальными векторными иконками (еда, напитки, сладкое, игрушки,
  электроника, книги, цветы, дом).
- Процедурный звук на WebAudio (без файлов), экраны результата и паузы, тосты.

### Этап 2 — уровни, карта, магазин, сохранения
- **60 уровней** в 8 тематических мирах по 8 уровней: Продукты, Сладкое, Книги, Игрушки,
  Техника, Цветы, Красота, Универмаг.
- **Карта уровней**: миры, звёзды по уровням, замки, бейджи механик (💥 бомбы, ❄ лёд,
  ★ золото), автопрокрутка к текущему уровню, итог «пройдено / звёзд».
- **Магазин** в трёх вкладках: *Отделы* (новые товары + постоянные бонусы), *Наборы*
  (тематические товары), *Оформление* (6 интерьеров, переключаются в любой момент).
  Покупки реально влияют на игру: расширенный ассортимент попадает на полки с 15-го
  уровня, бонусы (+ходы, +подсказки, +отмены, +% монет) применяются ко всем уровням.
- **Спецтовары**: золотые тройки (с 12-го уровня) — другая плитка, свечение, а за сбор
  +1 ход и +2 монеты; **заблокированные ячейки** (с 26-го) — их нельзя двигать;
  **целевые уровни** (с 30-го) — нужно убрать только отмеченные товары.
- **Сохранение в IndexedDB** (с fallback на localStorage): звёзды, монеты, открытые
  уровни, покупки, оформление, настройки звука и музыки, прогресс заданий дня. Запись с дебаунсом, чтение с миграцией
  и валидацией — битые данные не ломают игру.

### Этап 3 — лёд, бомбы, задания дня, музыка
- **Замороженные товары** (с 44-го уровня): товар примерзает к полке, его нельзя
  перетаскивать, но можно собрать тройку прямо на месте. Через 3 собранные тройки лёд
  тает сам; лёд видно на полке (оверлей со снежинкой) и в HUD (`❄ N`), при попытке
  сдвинуть замороженный товар игра подсказывает правило.
- **Бомбы** (с 36-го уровня): тройка с бомбой гарантированно убирает ещё три товара
  самого частого вида — взрыв со вспышкой, тряской камеры и звуком; в HUD видно счётчик
  бомб (`💥 N`), в итогах уровня — число взрывов. Бомбы всегда убирают ровно тройку,
  поэтому правило «товары исчезают только тройками» не нарушается и уровни остаются
  проходимыми.
- **Задания дня**: три задания из девяти, одинаковые для всех на текущую дату, с
  прогресс-барами и наградой в монетах; счётчики (тройки, уровни, звёзды, золотые тройки,
  взрывы) копятся за день и сбрасываются в полночь. **Серия дней**: первая награда дня
  продлевает серию и платит бонус (+10 монет за каждый день серии, максимум +50), разрыв
  серии начинается заново. Кнопка «🎯 Задания» в главном меню, экран со списком, серия и
  таймер до обновления.
- **Музыка**: спокойный бесконечный луп (Am–F–C–G, мягкие пэды + колокольчик) на
  WebAudio, без файлов; переключатель в меню и в паузе, пауза при уходе со вкладки,
  настройка сохраняется вместе с остальными.

### Этап 4 — комбо и звёзды за прохождение
- **Комбо**: тройки, собранные подряд (одна за другой по ходам), копят серию. Каждая
  следующая тройка в серии платит всё больше монет (+2 за шаг, до +12 за ход), серия
  растёт и от одного хода с бомбой (она убирает сразу две тройки). Ход «впустую» или
  отмена сбрасывают серию, лучшая серия уровня сохраняется и попадает в итоги.
  В HUD — плашка «🔥 Комбо ×N» с суммой, на полке — всплывающее «Комбо ×N» и искры.
- **Три уровня прохождения** вместо просто «звёзд за остаток ходов»:
  - ⭐ **Победа** — уровень пройден;
  - ⭐⭐ **Хорошее прохождение** — пройден с запасом ходов или без единой подсказки;
  - ⭐⭐⭐ **Идеальное прохождение** — без подсказок, отмен и бустеров и с солидным запасом
    ходов (не меньше порога третьей звезды уровня).
  Подсказка, отмена или бустер закрывают путь к третьей звезде, но не мешают заработать
  вторую.
- **Награды**: к базовой награде и бонусу за звёзды добавились монеты за комбо, за
  прохождение «без подсказок, отмен и бустеров» (+15) и за каждый сэкономленный ход
  (+2, до +30).
  На экране результата видно полное построчное объяснение: за что именно заплатили.

### Этап 5 — бустеры
- **🔨 Молоток** — убирает один товар с полки (в том числе замороженный: лёд тает вместе с
  ним). Стоит один бустер, не тратит ход.
- **🔀 Перемешивание** — переставляет доступные товары по полкам так, что готовых троек
  после этого не появляется; заблокированные и замороженные товары остаются на месте.
- **➕ +3 хода** — добавляет три хода к запасу уровня (и к его бюджету, чтобы счётчик
  израсходованных ходов и пороги звёзд остались осмысленными).
- **↩ Бесплатная отмена** — кладёт в запас ещё одну отмену.
- Инвентарь бустеров хранится в прогрессе (IndexedDB) и выдаётся стартовым набором
  (2/2/1/2). Старые сохранения получают набор при миграции. Панель бустеров живёт в HUD,
  пустые кнопки гаснут, у молотка есть режим прицеливания с подсветкой товаров.
- **Бустеры не ломают solver и генератор**: они применяются к доске в рантайме, а генератор
  по-прежнему проверяет уровни без их участия. Чтобы молоток не мог сделать уровень
  непроходимым, в цели появилось правило: **остаток меньше тройки (1–2 товара) больше не
  считается целью** — такие товары всё равно нельзя собрать. На экране результата видно
  «На полке осталось N — пару уже не собрать, цель засчитана».
- Бустеры — это помощь, поэтому они закрывают путь к ⭐⭐⭐, как подсказки и отмены
  (⭐ или ⭐⭐ при этом заработать не мешают).

### Этап 6 — развитие магазина

- **Магазин стал системой развития**: у каждого купленного отдела 5 уровней. Уровень
  покупается за монеты и даёт постоянный бонус — `+1 ход`, `+1 подсказка`, `+1 отмена`,
  `+5…10 % монет`. На последнем уровне отдела в инвентарь падает бустер.
- **Магазин растёт визуально**: суммарный уровень отделов превращает заведение из «Лавки»
  в «Магазин» → «Универмаг» → «Пассаж» → «Галерея». В шапке магазина видно название ранга,
  полосу прогресса до следующего ранга и ромбы-ступени; на верхних рангах подложка,
  свечение и тени ранга меняются по CSS.
- **Вкладка «Развитие»**: карточка на каждый отдел с уровнем-пипсами, текстом следующей
  награды и кнопкой «Улучшить», плюс **покупка бустеров поштучно** (🔨 70, 🔀 60, ➕ 90,
  ↩ 50 монет) — небольшой повторяемый сток монет.
- Бонусы отделов-покупок и уровней развития складываются; старые сохранения получают
  пустой набор уровней, а неизвестные/завышенные значения уровней отбрасываются и
  обрезаются при миграции.
- Экономика: каталог магазина — 4 600 монет, полное развитие отделов — 6 845 монет.
  Кампания с одной звездой даёт ~7 000, хорошее прохождение ~10 000, а с бонусом монет
  от развития — до ~19 000, так что развитие закрывается постепенно (задания дня помогают).

### Этап 7 — подарок дня

- **Календарь на семь дней**: первый заход в день забирает подарок своей ячейки.
  Награда растёт по дням серии — 40, 60, 80, 100, 130, 160, 220 монет, — а на 3, 5, 6 и 7
  день в подарок идёт бустер (перемешивание, отмена, молоток, «+3 хода»). Полный круг —
  790 монет и 4 бустера, дальше календарь повторяется.
- **Пропустил день — серия и календарь начинаются заново**; серия считается по тому же
  `dailyStreak`, что и бонус за задания дня (+10 за день, до +50), поэтому обе награды
  делят одну серию и не начисляют её дважды.
- **Время — не только локальное**: `src/data/clock.ts` держит единственную точку входа
  «какой сегодня день». По умолчанию это часы устройства, но адаптер Yandex Games SDK вызовет
  `setTrustedTime(...)`, и все дневные системы — задания, серия и подарок — переключатся на
  доверенное время без правок в остальных модулях.
- **Календарь нельзя отмотать назад**: в сохранении лежит `lastSeenDay`, и `resolveDay`
  берёт максимум из локального дня и сохранённого. Перевод часов назад не открывает уже
  сыгранный день, а абсурдный прыжок вперёд (> 30 дней) считается сбитыми часами, чтобы
  игрок не остался без подарков на месяцы.
- На экране видно серию, семь ячеек с наградами (получено / сегодня / впереди), кнопку
  «Забрать подарок» и обратный отсчёт до следующего; в меню кнопка «🎁 Подарок» помечается
  значком, пока подарок не забран. Экономика: в среднем 113 монет в день — каталог
  (4 600) и полное развитие (6 845) остаются долгой целью, а не выдаются сразу.

### Этап 8 — режим МАСТЕР

- **Новых уровней нет**: режим открывается после 60-го уровня и переигрывает кампанию
  с модификаторами. Мастер-уровень — чистая функция от обычного (`buildMasterLevel`),
  id живут отдельно (`1000 + id`), поэтому реестр уровней не меняется.
- **Модификаторы** (данные в `master.ts`, у каждого — иконка, название и пояснение):
  ⏳ мало ходов (сверх решения всего 10 % вместо 130–35 %), 🚫 без подсказок (даже купленных
  в магазине — `LevelConfig.noHints` перебивает бонусы), 🧊 больше льда, 🔒 больше блоков,
  ✨ больше золотых и бомбовых троек. Набор зависит только от номера уровня и не меняется,
  так что уровень можно выучить. Ходов всегда не больше, чем в кампании, и никогда не
  меньше, чем требует проверенное решение: модификаторы считают свободные тройки-слоты и
  добавляют ровно столько, сколько помещается.
- **Награда — короны и очки мастерства**: за победу 1–3 короны (по звёздам) и
  `10 + 6×звёзды + 5×модификаторы` очков. Очки идут только за личный рекорд уровня, поэтому
  переигрывать лёгкие уровни бессмысленно, а короны не понижаются при слабом повторе.
  Ранги: Стажёр → Продавец (120) → Старший продавец (300) → Управляющий (600) → Мастер полок
  (1000). Мастер-прохождение **не** трогает звёзды и открытые уровни кампании — только монеты.
- Экран «Мастер» показывает ранг с полосой до следующего, короны 👑 из 177 (59 × 3), сетку
  уровней с иконками модификаторов и лучшим результатом; карточка уровня показывает список
  модификаторов и награду, кнопка «Играть МАСТЕР» запускает заход. В бою в HUD висит чип
  «👑 МАСТЕР» с модификаторами, на экране результата — короны, +очки и повышение ранга.

### Этап 9 — временные события

- **Событие — это запись в конфиге** (`src/data/events.ts`): расписание, набор заданий и финальный
  приз. Движок не знает ни одного названия события — он спрашивает данные «что идёт сегодня» и
  «на сколько вырос счётчик», поэтому новое событие добавляется одной записью в `EVENTS`.
  Сейчас в ротации три события: 🧁 «Неделя сладостей», 📱 «Дни техники», 🌷 «Фестиваль цветов».
- **Расписание двух видов**: `{ kind: 'rotation' }` — неделя по кругу (якорь — понедельник
  2026-01-05, событие всегда идёт Пн–Вс, номер недели берётся из игровых часов) и
  `{ kind: 'window', from, to }` — жёсткие даты для праздничного события (окно приоритетнее
  ротации, проверено тестом на конфиге, которого нет в игре).
- **Задания считаются таблицей метрик**: `EVENT_METRICS` — это чистые функции от одного хода
  (`cleared`, `triples`, `golden`, `bomb`, `combo`, `won`, `stars`, `boostersUsed`). Новая метрика
  или новая категория товаров — строка в таблице, движок не меняется. Метрики: тройки, тройки
  сладкого/техники/цветов, золотые тройки, взрывы, звёзды, уровни, комбо ×3, бустеры.
- **Награды**: у каждого задания монеты (90–170) и, у части заданий, бустер; финал открывается
  после всех заданий и платит 500 монет плюс бустеры. Итог события попадает в историю
  (`Progress.eventWins`).
- **Прогресс события временный**: счётчики хранятся вместе с id события, при смене недели
  старые обнуляются (новая неделя — новые задания), а сохранение другого события при загрузке
  отбрасывается. День берётся из игровых часов, поэтому перевод часов назад не открывает
  прошедшее событие повторно.
- **В интерфейсе**: полоска события в меню с названием, таймером и значком «!», когда есть
  невыбранная награда; экран «Событие» — баннер с описанием и товарами, список заданий с
  прогрессом, бонусами и кнопками, карточка финала и подпись «событие идёт неделю».

### Этап 10 — площадка Яндекс Игр (SDK)

- **Отдельный слой площадки** `src/platform/`: `yandex.ts` — типизированная обёртка над
  `window.YaGames`, `i18n.ts` — язык интерфейса, `boot.ts` — последовательность запуска,
  `mock.ts` — локальная заглушка SDK. Игра нигде не обращается к SDK напрямую: любой вызов
  переживает отсутствие площадки и ведёт себя как обычный веб-билд.
- **Подключение ровно по документации**: динамически вставляется `<script async src="/sdk.js">`
  (относительный путь — требование площадки), после загрузки — `YaGames.init()`. Ошибка загрузки,
  исключение в `init()` или молчание дольше таймаута переводят игру в режим `web`, а не ломают
  запуск. Поля `environment.app.id`, `payload`, `referrer` читаются и попадают в состояние.
- **Язык** берётся из `ysdk.environment.i18n.lang` (требование 2.14) в порядке:
  `?lang=` → язык портала → `ru`. Локали `ru/be/kk/uk/uz/ky/tg/…` идут в русский интерфейс,
  остальные — в английский. Английский переведён для меню, HUD, паузы и итогов уровня;
  экраны, которых перевод ещё не касался (магазин, задания, события), остаются на русском —
  лучше цельный русский экран, чем наполовину переведённый. Язык фиксируется до первого рендера,
  при смене дерево перемонтируется (в `main.tsx` ключ `App`), поэтому строки не «мигают».
- **Разметка загрузки и игры**: `LoadingAPI.ready()` вызывается, когда меню показано и
  интерактивно; `GameplayAPI.start()/stop()` включаются ровно по фазе игры (уровень — идёт,
  меню/пауза/итоги/реклама — нет). Соответствие фазы и разметки держит одна подписка на store.
- **Пауза площадки**: `game_api_pause` глушит звук (`audio.suspend()`), ставит игру на паузу и
  запоминает фазу, `game_api_resume` возвращает игру туда, где она была. Если игрок сам стоял в
  меню паузы — он там и остаётся; если игра была остановлена площадкой, разметка не включается
  заново (`start()` не дёргается повторно).
- **Доверенные часы**: `ysdk.serverTime()` уходит в `setTrustedTime()` из этапа 7, поэтому
  подарок дня, задания дня и события считаются по времени сервера, а перевод системных часов
  назад перестаёт что-либо открывать. Время обновляется при каждом `game_api_resume`.
- **Фуллскрин**: статус читается через `ysdk.screen.fullscreen` (у площадки нет события смены,
  поэтому статус опрашивается раз в 500 мс), кнопка «Во весь экран» добавлена в меню паузы и
  работает как через SDK, так и через браузерный Fullscreen API на обычном вебе.
- **Проверка без площадки**: `?sdk=mock` поднимает заглушку с настоящим набором вызовов
  (`environment`, `LoadingAPI`, `GameplayAPI`, `on/off`, `serverTime`, `screen.fullscreen`) —
  удобно и для локального превью, и для тестов; `?lang=en` показывает английский интерфейс.

### Этап 11 — облачные сохранения

- **Локальное сохранение остаётся основным**: IndexedDB (с фолбэком на `localStorage`) пишет
  прогресс сразу после действия, облако — его зеркало. Игра не ждёт сеть: `hydrate()` сначала
  поднимает локальный сейв и показывает меню, а облачная сессия догоняет в фоне.
- **Что уезжает в облако** — весь сейв целиком: уровни и звёзды, монеты, купленные отделы и
  интерьеры, развитие магазина, бустеры, короны и рекорды МАСТЕРА, история событий, серия
  подарков, счётчики дня и настройки. Один ключ `save` (документация разрешает 200 КБ, наш
  сейв — несколько килобайт), плюс числовая выжимка (`player.setStats()`: звёзды, уровень,
  монеты, короны, очки мастерства, серия) — её будут читать лидерборды и аналитика на
  следующих этапах.
- **Сохранение идёт сразу после действия**: автосейв стора пишет локально с задержкой 0.6 с и
  зеркалит в облако с задержкой 4 с и не чаще одного раза в 10 секунд (лимит SDK — 100 запросов
  за 5 минут), а `visibilitychange`, `pagehide` и `game_api_resume` дожимают оба сейва. Игрок
  нажал «Пауза» — на паузе всё уже сохранено.
- **Старые сейвы мигрируют сами**: у сейва появилась метка времени `savedAt` (`0` — сейв из
  версии до облака), а формат версии проверяется: сейв из будущей версии игра не пытается
  «починить», а отвергает облачную копию целиком.
- **Правила разрешения конфликтов** (`decideSync`, чистая функция, 8 тестов):

  | Ситуация | Что происходит |
  |---|---|
  | В облаке пусто | локальный сейв уезжает в облако |
  | Облако пустое, локально есть прогресс | уходит локальный (пустое облако не затрёт прогресс) |
  | Свежая установка (`rank` пустого сейва) | втягивается облачный сейв |
  | Локальный сейв из версии до облака | сравнение по прогрессу, а не по часам |
  | Оба сейва реальные | новее по `savedAt` (доверенные часы), разница < 5 с — по прогрессу |
  | В облаке сейв другого аккаунта | берётся он (свой прогресс на чужой аккаунт не подсаживается) |
  | Игрок нажал «сбросить прогресс» | метка `wipe` заставляет перезаписать облако, а не тянуть старое |
  | Сеть отвалилась | играем локально, статус «есть несохранённые изменения», синхронизация по кнопке |

  «Дальше» считается по `progressRank`: звёзды, открытый уровень, покупки, развитие, короны,
  рекорды, победы в событиях, серия. Монеты и бустеры в ранг не входят — иначе трата выглядела
  бы как откат, и старая облачная копия затирала бы новый прогресс.
- **Проверка руками**: в паузе появилась карточка «Облачное сохранение» — статус (зелёная точка —
  синхронизировано, жёлтая — есть что отправить), кнопка «Синхронизировать» и, для гостя, «Войти
  в Яндекс» (`ysdk.auth.openAuthDialog()`, после входа сессия пересобирается).
- **iOS**: если `ysdk.getStorage()` доступен, подсистема сохранений переключается на него —
  документация предупреждает, что на новых iOS обычный `localStorage` часто очищается.
- **Консоль разработчика**: в черновике нужно поставить галочку «Облачные сохранения» (пункт 1.11
  требований); для проверки — панель отладки (`&debug-mode=16`) и кнопка ☁️ «Clear cloud data»,
  а также ⚒️ 🐢 (плохая сеть) и 👁 (потеря фокуса).
- **Что дальше**: реклама (этап 12), лидерборды (13) и аналитика (14) используют этот же слой —
  `setStats()` уже пишет те числа, которые понадобятся рейтингу.

### Этап 12 — реклама

- **Только официальный SDK**: игра использует `ysdk.adv` (`showFullscreenAdv`,
  `showRewardedVideo`, `getBannerAdvStatus` / `showBannerAdv` / `hideBannerAdv`) и ничего
  больше — никаких сторонних сетей. Свой слой (`src/platform/ads.ts`) знает про площадку одно:
  заглушка `?sdk=mock` подменяет её так же, как и раньше.
- **Межстраничная реклама — только на логических паузах**, по явному нажатию: «Дальше» на
  экране победы, «Заново» после победы и после проигрыша. Вызов уходит прямо из обработчика
  клика — требования площадки разрешают задержку между действием и рекламой не больше 2 секунд
  (пункт 4.4), поэтому таймеров здесь нет. Ни во время партии, ни после хода, ни на всплывашке
  реклама не показывается: случайные клики рядом с крестиком площадка считает рекламным
  мошенничеством.
- **Гейт частоты** (`interstitialReady()` возвращает причину отказа):

  | Правило | Значение |
  |---|---|
  | между рекламами | не чаще одного раза в 3 минуты (метка в `localStorage` — переживает перезагрузку) |
  | между рекламами | минимум 2 пройденных уровня (считаются только победы) |
  | за сессию | не больше 8 показов |
  | во время партии | отказ `in-play` — реклама не появляется между ходами |
  | реклама уже открыта | отказ `busy` — второй вызов ждёт |
  | куплено «Без рекламы» | отказ `off` — пункт 4.4: игра, продающая отключение рекламы, не показывает межстраничную |

  Если площадка отказала (лимит, нет соединения), `onClose` всё равно приходит: интервал
  начинается заново, а игра продолжается как обычно — «Дальше» просто открывает следующий
  уровень. Кнопки никогда не «залипают»: когда реклама не разрешена, переход выполняется
  синхронно, без ожидания.
- **Ролик за награду — только добровольно** и только за награду: «Ещё 3 хода» на экране
  проигрыша (оживление — раз за заход), «Удвоить награду» на экране победы (см. ниже),
  «+60 монет» (3 раза в день) и случайный бустер (1 раз в день) в магазине, в блоке
  «За просмотр рекламы». Награда выдаётся **только в
  `onRewarded`**, то есть после подтверждённого просмотра: закрыл ролик раньше — награды нет
  и дневная квота не тратится. Кнопка показывает остаток квоты и сама гаснет на «На сегодня всё».
  Ролики могут вызываться сколько угодно раз — это ограничение площадки не на них, а на
  межстраничную рекламу.
- **«Удвоить награду» на экране победы** — четвёртая добровольная точка: после победы игрок
  может посмотреть ролик и получить ровно столько же монет, сколько принёс уровень. Один раз
  за заход, и удвоение тратит ту же дневную квоту монет за рекламу, что и магазин, — экономика
  остаётся ограниченной сверху. Кнопка исчезает у тех, кто купил «Без рекламы».
- **Игра замирает на время рекламы**: звук и музыка уходят в `suspend()`, Phaser-сцена встаёт,
  а баннер и подсказки прячутся — игрок не нажимает по полю, пока реклама на экране
  (и не теряет ход). После закрытия всё возвращается, и только тогда играет переход к уровню.
- **Липкий баннер** показывается через API (если в Консоли включена галочка «Использовать API
  для показа липкого баннера») и **прячется на время партии** — во время игры баннер не
  перекрывает нижнюю полку. Если реклама не подключена, `getBannerAdvStatus` вернёт
  `ADV_IS_NOT_CONNECTED`, и игра спокойно работает без баннера.
- **Настройки в Консоли разработчика**: вкладка «Реклама» — размещение липкого баннера и галочка
  API для него. Галочку «отключать рекламу покупателям» включать не нужно: с внеочередного шага
  игра сама продаёт товар «Без рекламы» и сама выключает межстраничную рекламу и баннер
  (см. раздел «Покупки, флаги и сборка архива»). Проверять реальные рекламные ролики нужно
  в проде или в черновике; в песочнице удобны заглушка (`?sdk=mock`) и панель отладки
  (`&debug-mode=16`).
- **Что дальше**: лидерборды (этап 13) и аналитика (этап 14) — события показов уже сходятся в
  `AdsStatus` (`interstitials`, `rewarded`, `last`, причина отказа), её и будет читать аналитика.

### Оформление и звук (после этапа 13)

Отдельный проход «повысить качество» по внешнему виду и звуку — механики не менялись, только то,
как игра их показывает и озвучивает.

- **Частицы вместо точек**: у эффектов появились мягкое свечение, четырёхлучевые «искры»,
  ленты конфетти и дым. Взрыв бомбы теперь даёт разлёт обломков с гравитацией и облачко пыли,
  золотая тройка — блик по плитке и восходящее шиммер-арпеджио, комбо — свечение по краям
  экрана, тем ярче, чем длиннее серия. Победа — дождь из искр поверх конфетти.
- **Вес и инерция у перетаскивания**: товар поднимается (тень на полке, наклон по скорости
  движения, световой след), а приземляется с squash-and-stretch вместо простого переноса.
  Пульс золотых и бомбовых плиток при этом не сбивается: он ставится на паузу на время
  перетаскивания и возвращается после.
- **Тёплый звук**: у мастера появился компрессор (всплески больше не срезают друг друга) и
  маленький сгенерированный «зал» (свёрточный ревербератор на 1.6 с) — игра звучит не «в
  браузере», а в комнате. Стерео: звук совпадения сдвинут в сторону полки, где он случился;
  повторяющиеся щелчки получают микро-расстройку в центах, поэтому серия ходов не превращается
  в пулемёт. У музыки появились арпеджио-перебор по аккорду бара и мягкий шейкер на слабых
  долях; аккорд разложен по стереополю.
- **Интерфейс**: анимация появления экранов, тень у кнопок, реакция на наведение и чёткие
  focus-ring'и для клавиатуры, счётчик монет подпрыгивает при изменении, третья звезда светится
  сильнее (и каждая звезда получила собственный градиент — раньше три SVG делили один `id`),
  аккуратные скроллбары и выделение текста.
- **Доступность**: `prefers-reduced-motion` учитывается в обеих половинах игры — CSS глушит
  анимации интерфейса, а `src/game/juice.ts` снижает бюджет эффектов (меньше частиц, без тряски
  камеры и zoom, без squash). Всё важное остаётся видимым: лёгкий всплеск и подсказки сохраняются.

### Покупки, флаги и сборка архива (внеочередной шаг)

Три вещи вместе, потому что они отвечают на один вопрос «как выложить игру в Консоль и
крутить её после публикации без новой сборки».

#### Покупки (`src/platform/purchases.ts`)

- **Только официальный API** `ysdk.payments`: `getCatalog()`, `purchase({ id })`,
  `getPurchases()`, `consumePurchase(token)`. Игра считает покупки на клиенте (без `signed`),
  своего сервера у неё нет; на боевом хостинге объект берётся как `ysdk.payments`, а
  `getPayments()` остаётся запасным входом для старой сборки SDK.
- **Пять товаров**, они же id для вкладки «Покупки» в Консоли (строки должны совпадать
  символ в символ, иначе магазин просто не покажет товар):

  | id | Товар | Что даёт | Тип |
  |---|---|---|---|
  | `coins_small` | Горсть монет | 1 200 монет | расходуемый |
  | `coins_big` | Мешок монет | 4 000 монет | расходуемый |
  | `boosters_pack` | Набор бустеров | по 5 молотков, перемешиваний, отмен и 3 доп. хода | расходуемый |
  | `starter_pack` | Стартовый набор | 2 500 монет и по 3 бустера каждого вида | расходуемый |
  | `remove_ads` | Без рекламы | межстраничная реклама и баннер выключаются навсегда | постоянный |

- **Цены берутся только у площадки**: блок «Премиум» рисуется из `getCatalog()`
  (`price`, `priceValue`, `priceCurrencyCode`, `getPriceCurrencyImage()`), своих валют и
  курсов в игре нет — этого требует пункт 1.13.2. Товар из Консоли, которого игра не знает,
  не показывается; когда каталог пуст, блок объясняет, что покупки живут в Яндекс Играх.
- **Обязательная проверка необработанных покупок при каждом запуске** (пункт 1.13.1):
  `initPurchases()` забирает `getPurchases()` и выдаёт всё, что площадка ещё держит, —
  покупку, оплаченную при оборвавшейся сети, игрок получит при следующем запуске.
- **Сначала награда, потом `consumePurchase`** — порядок из документации: расходуемый товар
  после вызова исчезает навсегда, поэтому монеты и бустеры сначала попадают в сейв (и уезжают
  в облако), и только затем покупка закрывается. Если сеть отвалилась на закрытии, товар
  останется у площадки и придёт снова — потерять оплаченное игрок не может.
- **Постоянный товар не расходуется**: `remove_ads` приходит в `getPurchases()` всегда,
  поэтому он запоминается в локальном реестре (`shelf-sort:purchases:owned`), а игра
  спрашивает про него через `ownedBeforeSession()`. Пока покупка есть — межстраничная реклама
  и липкий баннер выключены (`adsOff` в `platform/ads.ts`), а ролики за награду остаются
  доступными: их смотрят только по желанию.
- **Без площадки** модуль сообщает `disabled` / `no-platform`, магазин показывает заглушку,
  игра работает как раньше. Покупки при этом не «залипают»: награда начисляется через хост
  `connectPurchases({ apply })`, который отдаёт магазин (`applyPurchaseReward` в сторе).

#### Флаги экспериментов (`src/platform/flags.ts`)

- **Один запрос на старт**: `ysdk.getFlags({ defaultFlags, clientFeatures })` вызывается один
  раз (после загрузки сейва, чтобы `clientFeatures` знал уровень, звёзды и `payingStatus`).
  В `defaultFlags` всегда уезжает вся локальная конфигурация — если Консоль молчит, игра
  остаётся на своих значениях.
- **Шесть флагов** (та же таблица — заготовка для вкладки «Флаги»; всё числовое зажимается
  в разумные границы):

  | Флаг | Значение по умолчанию | Что меняет |
  |---|---|---|
  | `ads_min_interval_min` | 3 | минимальный интервал между межстраничными, минуты |
  | `ads_levels_between` | 2 | сколько уровней проходит между показами |
  | `ads_max_per_session` | 8 | потолок показов за сессию |
  | `ad_reward_coins` | 60 | монет за просмотренный ролик |
  | `ad_rewards_per_day` | 3 | сколько раз в день ролик платит (удвоение награды входит в квоту) |
  | `coins_multiplier` | 1 | множитель монет за уровни (A/B экономики) |

- **Порядок старшинства**: `?flags=` в адресе → ответ площадки → кэш последнего удачного
  чтения (в `localStorage`) → локальные значения. Успешный ответ площадки авторитетен: флаг,
  удалённый в Консоли, возвращается к значению по умолчанию, а не остаётся жить в кэше.
- **Никогда не блокирует игру**: 6 секунд ожидания, любая ошибка — просто локальные значения,
  `FlagsStatus` при этом рассказывает UI, откуда взялись числа.
- **Проверка без Консоли**: `?flags=ad_rewards_per_day=5,coins_multiplier=2`. Заглушка SDK
  поддерживает и `getFlags` (ключ `flags` в `createMockSdk`), так что эксперимент виден
  в `?sdk=mock`.

#### Сборка архива для Яндекс Игр (`npm run package`)

Скрипт `scripts/package-yandex.mjs` собирает ровно то, что ждёт Консоль, и проверяет правила
площадки до загрузки:

```bash
npm run package                 # tsc -b + vite build --base=./ + ZIP
node scripts/package-yandex.mjs --check        # только проверить dist/ без сборки ZIP
node scripts/package-yandex.mjs --out=my.zip   # свой путь
```

- Сборка идёт с **относительными путями** (`--base=./`): площадка отдаёт архив со своего
  пути, и абсолютные `/assets/...` там бы не нашлись. Скрипт падает, если в `index.html`
  появилась ссылка вида `/…`.
- **Один `index.html` в корне архива** (пункт 1.22), ровно один; имя без пробелов и
  кириллицы; распакованный размер ≤ 100 МБ (пункт 1.21, у нас ~1,6 МБ).
- **Внешние адреса** (картинки, шрифты, скрипты) перечисляются предупреждением: данные игры
  должны лежать внутри архива, чужой хост требует письменного согласования.
- ZIP пишется вручную на `node:zlib` — без `zip`, без зависимостей, поэтому `npm run package`
  ведёт себя одинаково на любой машине. Результат: `artifacts/shelf-sort-yandex.zip`.
- В конце печатается чек-лист Консоли: архив (General → Archive), товары, реклама,
  флаги, лидерборды, галочка «Облачные сохранения».

### Этап 13 — рейтинг (лидерборды)

- **Только официальный API площадки**: `ysdk.leaderboards.getEntries` / `setScore` (объект берётся
  напрямую из `ysdk.leaderboards`; устаревший `ysdk.getLeaderboards()` оставлен как запасной
  путь для старых сборок SDK). Своих серверов у игры нет.
- **Три таблицы**, все числовые и по убыванию (`numeric`, `Descending`):

  | Техническое имя | Что показывает | Откуда берётся |
  |---|---|---|
  | `shelf_mastery` | очки мастерства (главная таблица) | сумма лучших очков по каждому уровню МАСТЕРА |
  | `shelf_stars3` | уровней на ⭐⭐⭐ | сколько уровней кампании пройдено на три звезды |
  | `shelf_week` | лучший результат недели | рекорд по звёздам за одну неделю (ISO, понедельник–воскресенье) |

  Все три значения считаются по **лучшим** заходам и никогда не уменьшаются — площадка хранит
  результат игрока и не даёт его отозвать, поэтому в игре нет ничего, что могло бы отправить
  меньший результат. «Лучший результат недели» — это именно рекорд недели: таблицу нельзя
  перезапускать каждый понедельник, зато рекорд честно объясняется игроку в подсказке к вкладке.
- **Отправка только улучшений**: `setScore` вызывается, если новое значение больше уже
  отправленного (метки лежат в `localStorage` и переживают перезагрузку), не чаще одного раза
  в секунду — это документированный лимит метода, поэтому запросы идут через очередь с
  интервалом 1,1 с. Свежий игрок с нулём звёзд не отправляет ничего.
- **`setScore` — только для вошедших**: перед вызовом проверяется
  `ysdk.isAvailableMethod('leaderboards.setScore')`, а гость ничего не отправляет (как и требует
  документация). Гости при этом видят топ таблицы: `getEntries` доступен без авторизации,
  а своё место (`userRank`) в ответе появляется только у вошедших.
- **Бюджеты запросов соблюдены**: `getEntries` — 20 запросов за 5 минут, поэтому таблица
  читается по требованию и кэшируется на минуту (кнопка «Обновить» сбрасывает кэш);
  `getPlayerEntry` (60 запросов за 5 минут) не вызывается вовсе — место игрока приходит из
  `getEntries` с `includeUser: true` и `quantityAround: 3`.
- **Игра работает без рейтинга.** Экранов-заглушек нет: вкладка «Рейтинг» в меню открывается
  всегда и честно объясняет состояние — «Рейтинг доступен в Яндекс Играх» (веб-версия),
  «Таблицы рейтинга ещё не подключены» (нет API или выключенный метод), «В таблицу попадают
  только игроки, вошедшие в Яндекс» с кнопкой «Войти в Яндекс» (та же авторизация, что и у
  облачных сохранений), «Такой таблицы нет в Консоли разработчика: `shelf_mastery`» (ошибка 404
  из документации) и «Рейтинг не ответил — попробуйте обновить позже» (сеть). Любая ошибка
  оставляет игру играбельной: проигравшая отправка просто повторяется при следующем улучшении.
- **Что видно в таблице**: топ-10, три соседа сверху и снизу от игрока, имя, аватар
  (`player.getAvatarSrc('small')`) и место; своя строка подсвечена. Скрытые профили
  («User is hidden» из документации) показываются как «Игрок» без аватара.
- **Консоль разработчика**: вкладка «Лидерборды» → создать три таблицы с техническими именами
  `shelf_mastery`, `shelf_stars3`, `shelf_week`, тип «Число», сортировка по убыванию, у
  `shelf_mastery` включить «Главная таблица». Имена нельзя переиспользовать после удаления, а
  404 в консоли браузера означает ровно одно — таблицы с таким именем в черновике нет.
- **Проверка руками**: `http://localhost:5173/?sdk=mock` — заглушка поднимает три таблицы с
  придуманными игроками («Аня», «Борис»), отправка видна в её счётчиках, а вход в Яндекс
  открывает заглушечный диалог авторизации. В проде таблицы появляются после первой победы.
- **Что дальше**: аналитика (этап 14) и публикация (этап 15) — `player.setStats()` уже пишет
  те же числа, а `leaderboard.sent` покажет, что именно уехало в рейтинг.

## Прогрессия уровней

| Уровни | Полки | Троек | Типов | Свободно | Новое |
|--------|-------|-------|-------|----------|-------|
| 1      | 5 × 6 | 5     | 4     | 50 %     | обучающий уровень |
| 2–13   | 4–5 × 6 | 3–4 | 3     | 70 % → 60 % | золотые тройки (12+) |
| 14–25  | 5 × 6 | 5–6   | 3–4   | 50 %     | заблокированные ячейки (26+) |
| 26–39  | 6 × 6 | 6–8   | 4–5   | 42 % → 33 % | целевые уровни (30+) |
| 40–54  | 6–7 × 6 | 9–11 | 5–6   | 36 % → 29 % | бомбы (36+), лёд (44+), две золотые тройки |
| 55–60  | 7–8 × 6 | 11–12 | 6–7   | 31 % → 25 % | всё сразу |

Бюджет ходов считается от проверенного решения (`par`) с запасом, который плавно
уменьшается с 130 % до 35 %; пороги звёзд выводятся из бюджета.

## Архитектура

```
src/core/      — правила без Phaser/React (чистые функции, покрыты тестами)
  board / match / moves / goal / generate / solver / specials / combo / boosters / rng
src/data/      — данные: товары, иконки, темы, магазин, задания дня, конфиги уровней
  items.ts        24 товара и категории
  iconShapes.ts   иконки как векторные примитивы 100×100 (Phaser + SVG)
  themes.ts       8 миров: пул товаров и названия уровней
  shop.ts         каталог магазина: отделы, наборы, интерьеры, бонусы
  upgrades.ts     развитие магазина: 6 веток по 5 уровней, ранги магазина, цены бустеров
  master.ts       режим МАСТЕР: модификаторы уровней, короны, очки и ранги мастерства
  events.ts       временные события: расписание, задания, метрики и финальные призы
  dailies.ts      задания дня: пул заданий, выбор на день, серия и её бонус
  gift.ts         подарок дня: календарь на 7 дней, растущие награды и бустеры
  clock.ts        игровые часы: локальное время по умолчанию, доверенное (сервер) — когда есть
  levels/         level1 (ручной) + campaign (60 конфигов с кривой сложности)
src/game/      — Phaser: сцена, ввод, звук (+ музыка), эффекты, motion-бюджет, рантайм, вёрстка
src/store/     — Zustand (фаза, рантайм, прогресс, настройки) + persistence (IndexedDB)
src/platform/  — площадка Яндекс Игр: SDK, игрок, облака, реклама, покупки, флаги, рейтинг,
                 язык, запуск, заглушка
src/ui/        — React: меню, HUD, карта, магазин, задания дня, подарок, МАСТЕР, событие, оверлеи
src/test/      — 519 тестов (включая UI-интеграцию в jsdom, SDK-заглушку, текстуры плиток,
                 проверку сборки архива и фонов экранов)
scripts/       — package-yandex.mjs: боевая сборка в ZIP для Консоли без внешних зависимостей;
                 screen-styles.mjs: страж фонов (под каждым экраном не должно быть видно сцену)
```

Уровень — это данные (`LevelConfig`): полки, пул товаров, цель, бюджет ходов, подсказки,
отмены, монеты. Добавить уровень = добавить конфиг, движок менять не нужно.

### Гарантия «нет непроходимых уровней»

1. Товары всегда кратны трём, и за одно совпадение исчезает ровно три предмета — остатков
   не бывает (это же свойство проверено тестом). Бомба убирает ровно одну дополнительную
   тройку, поэтому свойство сохраняется и после взрывов. Единственное исключение — молоток:
   он честно убирает один товар, а оставшуюся пару цель просто не требует собирать.
2. Генератор раскладывает тройки, перемешивает их обратимыми ходами (на старте нет готовых
   троек), расставляет лёд и блокировки и **проверяет доску планировщиком с учётом цели
   уровня**; при неудаче берёт следующий сид. Планировщик умеет играть с новыми механиками:
   не двигает замороженные товары и учитывает взрывы.
3. Бюджет ходов выводится из длины проверенного решения, поэтому он всегда достижим.
4. Тест прогоняет все 60 уровней: генерирует, планирует и **выигрывает каждый уровень**,
   повторяя его собственное решение через настоящий движок.
5. Отдельный тест проходит поздние уровни (со льдом и бомбами) так, как играет человек —
   следуя подсказкам: лёд тает, бомбы взрываются, уровень выигрывается.

### Управление

- **ПК**: перетаскивание мышью; можно щёлкнуть товар и затем — пустую ячейку.
- **Телефон**: touch/drag с увеличенной зоной попадания; тап по товару подсвечивает
  свободные ячейки, второй тап переносит предмет.
